### **2\.1 入口方法: dispatchModules\(\)**

```Java
// 第 60 行
public FlowContext dispatchModules(ChatDispatchParam chatDispatchParam) {
    // ===== 阶段1: 加载节点 =====
    // 将前端 JSON → RunningModuleItemType (可执行节点)
    List<RunningModuleItemType> runningModules = loadModules(chatDispatchParam);
    chatDispatchParam.setRunningModules(runningModules);

    // ===== 阶段2: 构建运行时上下文 =====
    // 并发模式: create ExecutorService + CompletionService
    // 同步模式: 仅创建 switchMap
    FlowContext flowContext;
    flowContext = isConcurrencyExecute(chatDispatchParam)
            ? new FlowContextBuilder().buildExecutor(runningModules)
            : new FlowContextBuilder().build(runningModules);

    // ===== 阶段3: 注入全局变量 =====
    // 变量前缀 "global-" 防止与节点内部变量冲突
    dealGlobalVariable(flowContext, chatDispatchParam.getVariables());
    // 会话变量前缀 "session-" 跨对话持久化
    dealSessionVariable(flowContext, chatDispatchParam.getSessionVariable());

    // ===== 阶段4: 找到入口节点 =====
    // questionInput / historyNode / pluginInput / loopStart
    List<RunningModuleItemType> initModules = initRunningModuleType(runningModules);
    // 为入口节点注入初始参数
    moduleInput(initModules, chatDispatchParam.getStartParams());

    // ===== 阶段5: 模式分发 =====
    if (!isConcurrencyExecute(chatDispatchParam)) {
        checkModulesCanRunSync(initModules, flowContext, chatDispatchParam);  // 同步递归
    } else {
        checkModulesCanRun(initModules, flowContext, chatDispatchParam);      // 线程池并发
        flowContext.tryDestroy();  // 线程池销毁
    }
    return flowContext;
}
```

**面试要点**: 入口方法展示了 5 个核心阶段。关键在于 `loadModules` 处理前端 JSON、`initRunningModuleType` 自动找到入口节点、模式自动判断。

```Java
// 第 141 行 ─── 核心递归方法
private void checkModulesCanRunSync(
    List<RunningModuleItemType> modules,      // 当前批次的待执行节点
    FlowContext flowContext,
    ChatDispatchParam chatDispatchParam
) {
    for (RunningModuleItemType moduleItemType : modules) {
        // 1) 检查所有 input 是否有值
        if (moduleCanRun(moduleItemType)) {
            // 2) 注入 switchMap 中的动态变量
            moduleInput(moduleItemType, flowContext.getSwitchMap());

            // 3) 发送 SSE 状态通知 (前端实时展示执行进度)
            SSEUtils.pubMsg(reqId, "moduleStatus", {moduleName, status:1});

            // 4) ★ 执行单节点 ★
            Map<String, Object> response = moduleRun(moduleItemType, chatDispatchParam, flowContext);

            // 5) 发送 SSE 完成通知
            SSEUtils.pubMsg(reqId, "moduleStatus", {moduleName, status:2, details:...});

            // 6) ★ 处理输出 → 找到下游节点 ★
            List<RunningModuleItemType> nextRunModules =
                moduleOutput(moduleItemType, response, flowContext, chatDispatchParam);

            // 7) ★ 递归执行下游 ★
            if (!CollectionUtils.isEmpty(nextRunModules)) {
                checkModulesCanRunSync(nextRunModules, flowContext, chatDispatchParam);
            }
        }
    }
}
```

**面试要点**: 递归结构是 DAG 执行的核心。每个节点执行完成后，通过 `moduleOutput` 找到所有下游节点，然后递归调用自己。这不是简单的链式调用，而是一个**拓扑排序 \+ 深度优先**的 DAG 遍历。

### **2\.4 并发执行: checkModulesCanRun\(\)**

```Java
// 第 196 行 ─── 线程池并发模式
private void checkModulesCanRun(
    List<RunningModuleItemType> modules,
    FlowContext flowContext,
    ChatDispatchParam chatDispatchParam
) {
    // 1) CountDownLatch 协调所有并行任务
    CountDownLatch countDownLatch = new CountDownLatch(modules.size());

    // 2) 每个节点提交到 CompletionService
    for (RunningModuleItemType moduleItemType : modules) {
        if (moduleCanRun(moduleItemType)) {
            flowContext.getCompletionService().submit(() -> {
                try {
                    moduleInput(moduleItemType, flowContext.getSwitchMap());
                    Map<String, Object> response = moduleRun(moduleItemType, chatDispatchParam, flowContext);

                    Map<String, Object> map = new HashMap<>();
                    map.put("module", moduleItemType);
                    map.put("response", response);
                    return map;  // 返回给 CompletionService
                } finally {
                    countDownLatch.countDown();  // ← 无论成败都计数
                }
            });
        } else {
            countDownLatch.countDown();  // input 不满足的也计数
        }
    }

    // 3) 等待所有并行任务完成
    countDownLatch.await();

    // 4) 按完成顺序取结果 → 找下游 → 递归
    for (int i = 0; i < executeCount; i++) {
        Map<String, Object> map = flowContext.getCompletionService().take().get();
        // 找下游 → 递归 checkModulesCanRun(nextModules, ...)
        List<RunningModuleItemType> nextRunModules =
            moduleOutput(moduleItemType, response, flowContext, chatDispatchParam);
        checkModulesCanRun(nextRunModules, flowContext, chatDispatchParam);
    }
}
```

**面试要点**:

- `CountDownLatch` 确保所有并行节点完成后才进入下一批

- `CompletionService` 按完成顺序取结果（非提交顺序），先完成的节点优先找下游

- `finally` 中 `countDown()` 确保异常也不死锁

- 同级节点并行 → 下游节点递归 → 又遇同级并行 → 形成**分级并行 \+ 拓扑递归**

```Java
// 第 548 行 ─── 单节点执行
private Map<String, Object> moduleRun(
    RunningModuleItemType module,
    ChatDispatchParam chatDispatchParam,
    FlowContext flowContext
) {
    // 1) ★ 工厂模式获取执行器 ★
    String nodeType = module.getFlowType();
    ModuleService moduleService = moduleFactory.getService(FlowNodeTypeEnum.getType(nodeType));
    if (moduleService == null) {
        throw new FlowBusinessException("No action registered for node type: " + nodeType);
    }

    // 2) 组装 DispatchData
    DispatchData dispatchData = new DispatchData();
    BeanUtil.copyProperties(chatDispatchParam, dispatchData);
    // 将 input 列表 → key-value Map
    Map<String, Object> params = transParam(module.getInputs());
    dispatchData.setParams(params);
    dispatchData.setModuleInput(module.getInputs());
    dispatchData.setGlobalVariables(flowContext.getGlobalVariables());

    // 3) ★ 带超时 + 重试的执行 ★
    Map<String, Object> map = moduleService.executeWithTimeout(dispatchData);
    map.put("stepInputs", params);
    return map;
}
```

### **2\.6 超时 \+ 重试: ModuleService\.executeWithTimeout\(\)**

```Java
// ModuleService.java 第 25 行 ─── 接口默认方法
default Map<String, Object> executeWithTimeout(DispatchData dispatchData) {
    Map<String, Object> param = dispatchData.getParams();
    if (null != param.get("maxRuntime") && (int)param.get("maxRuntime") > 0) {
        int maxRuntime = (int)param.get("maxRuntime");
        // ★ 最多重试 3 次 ★
        int retryTime = Math.min((int)param.get("retryTime"), 3);

        ExecutorService executorService = FlowThreadPoolUtil.getSingleExecutor();

        for (int i = 0; i < retryTime; i++) {
            Future<Map<String, Object>> future = executorService.submit(() -> execute(dispatchData));
            try {
                result = future.get(maxRuntime, TimeUnit.SECONDS);  // 超时控制
                break;
            } catch (TimeoutException e) {
                future.cancel(false);  // 超时取消
            } catch (InterruptedException | ExecutionException e) {
                future.cancel(false);
                executorService.shutdown();
                throw new FlowBusinessException(e.getMessage());
            }
        }

        // ★ 重试耗尽 → 返回默认兜底值 ★
        if (!status && param.get("moduleDefaultOutput") != null) {
            result.putAll((Map<String, Object>) param.get("moduleDefaultOutput"));
        }
        return result;
    }
    return execute(dispatchData);  // 无超时配置 → 直接执行
}
```

**面试要点**: `maxRuntime` 秒级超时，最多重试 3 次，每次都 `future.cancel(false)` 取消旧任务。失败后返回 `moduleDefaultOutput` 兜底值，不会中断整个流程。

### **2\.7 节点输出处理: moduleOutput\(\)**

```Java
// 第 362 行 ─── 最关键的数据流转方法 (117 行)
private List<RunningModuleItemType> moduleOutput(
    RunningModuleItemType module,
    Map<String, Object> response,
    FlowContext flowContext,
    ChatDispatchParam chatDispatchParam
) {
    // ===== Step 1: 持久化回答文本 =====
    pushStore(module, response, flowContext);

    // ===== Step 2: 特殊节点处理 =====
    if (module.getFlowType().equals(ABILITY)) {
        return Collections.emptyList();  // Agent 调用后不找下游
    }
    if (module.getFlowType().equals(LOOP_BREAK)) {
        flowContext.setLoopEndCondition(response.get("condition"));
        return Collections.emptyList();  // 循环终止后不找下游
    }

    // ===== Step 3: 两种连接模式 =====
    List<RunningModuleItemType> nextRunModules = new ArrayList<>();

    if (null != outputConnect) {
        // ★ 模式A: outputConnect (中心化连接) ★
        // 所有 outputItem 通过 outputConnect.edges 找下游
        // → moduleInputGlobal() 注入全局变量
    } else {
        // ★ 模式B: Edge/Target (去中心化连接) ★
        for (outputItem : module.getOutputs()) {
            // B1: edges → 连接下游节点
            for (String edge : outputItem.getEdges()) {
                RunningModuleItemType target = flowContext.getModuleItemTypeMap().get(edge);
                nextRunModules.add(target);
            }
            // B2: targets → 精确赋值下游节点 input
            for (target : outputItem.getTargets()) {
                RunningModuleItemType targetModule = flowContext.getModuleItemTypeMap().get(target.getModuleId());
                // 按 target.key 赋值
                outputValue.put(target.getKey(), outputItem.getValue());
                moduleInput(targetModule, outputValue);
            }
            // B3: globalKey → 写入全局变量池
            if (outputItem.getGlobalKey() != null) {
                flowContext.getGlobalVariables().put(outputItem.getGlobalKey(), outputItem.getValue());
            }
        }
    }
    return nextRunModules;
}
```

**面试要点**: `moduleOutput` 是 DAG 数据流转的核心，支持三种下游连接方式:

1. **edges**: 粗糙连接 → 把下游节点加入 nextRunModules

2. **targets**: 精确连接 → 按 `target.key` 赋值下游节点的特定 input

3. **globalKey**: 跨路径连接 → 写入全局变量池，任何后续节点均可通过 `globalKey` 引用

```Java
// 第 618 行 ─── 转换 + 变量替换 + 过滤
public List<RunningModuleItemType> convertToRunningModules(
    List<ModuleItemType> modules,
    Map<String, Object> variables
) {
    // 1) 过滤非执行节点 (userGuide / noteNode)
    List<ModuleItemType> collect = modules.stream()
        .filter(m -> !m.getFlowType().equals(USER_GUIDE)
                   && !m.getFlowType().equals(NOTE_NODE))
        .collect(Collectors.toList());

    // 2) 转换每个节点
    collect.forEach(a -> {
        RunningModuleItemType item = new RunningModuleItemType();
        item.setModuleId(a.getModuleId());
        item.setFlowType(a.getFlowType());

        // 3) ★ 处理 Input ★
        // 过滤: 只保留 system_input / connected / 有默认值的 input
        List<FlowNodeInputItemType> inputs = a.getInputs().stream()
            .filter(i -> i.getType().equals(SYSTEM_INPUT)
                      || i.getConnected()       // 已连线的 input
                      || i.getValue() != null)  // 有默认值的 input
            .collect(Collectors.toList());

        // 4) ★ 替换全局变量占位符 ★
        inputs.forEach(i -> {
            RunningFlowNodeInputItemType type = new RunningFlowNodeInputItemType();
            type.setKey(i.getKey());
            type.setValueType(i.getValueType());
            // {{variable}} → 实际值
            type.setValue(
                (i.getValue() instanceof String)
                    ? MessageFormatUtils.replaceVariable((String) i.getValue(), variables)
                    : i.getValue()
            );
            type.setGlobalKey(i.getGlobalKey());
            inputList.add(type);
        });
        item.setInputs(inputList);

        // 5) ★ 处理 Output ★
        outputs.forEach(i -> {
            RunningFlowNodeOutputItemType type = new RunningFlowNodeOutputItemType();
            type.setKey(i.getKey());
            type.setEdges(i.getEdges());       // 边连接
            type.setTargets(i.getTargets());   // 目标连接
            type.setGlobalKey(i.getGlobalKey());// 全局变量 key
            outputList.add(type);
        });
    });
    return res;
}
```

**面试要点**: `loadModules` 做了三件事：

1. **过滤**非执行节点

2. **替换** `{{variable}}` 格式的全局变量占位符

3. **保留**三种 input \(system\_input/connected/有默认值\)，其余丢弃

## **ModuleFactory\.java 分析**

**文件**: `module/application/util/ModuleFactory.java` **行数**: 35 行 **职责**: 工厂模式 \+ Spring 注解扫描

```Java
@Component
public class ModuleFactory implements ApplicationListener<ApplicationReadyEvent> {

    // ★ 节点类型 → 执行器实例的映射 ★
    private Map<FlowNodeTypeEnum, ModuleService> typeToModuleServiceMap = new HashMap<>();

    public ModuleService getService(FlowNodeTypeEnum type) {
        return typeToModuleServiceMap.get(type);
    }

    @Override
    public void onApplicationEvent(ApplicationReadyEvent event) {
        // ★ 启动时扫描所有 @NodeType 注解的 Bean ★
        Map<String, ModuleService> moduleServiceMap =
            SpringUtil.getApplicationContext().getBeansOfType(ModuleService.class);

        for (ModuleService moduleService : moduleServiceMap.values()) {
            NodeType nodeType = moduleService.getClass().getAnnotation(NodeType.class);
            if (nodeType != null) {
                typeToModuleServiceMap.put(nodeType.value(), moduleService);
            }
        }
    }
}
```

**设计要点**:

1. 实现 `ApplicationListener<ApplicationReadyEvent>`，在 Spring 启动完成后统一注册

2. `getBeansOfType(ModuleService.class)` 扫描所有实现类

3. `getAnnotation(NodeType.class)` 读取注解获取节点类型

4. 简单查表 `getService(type)` 获取执行器，O\(1\) 复杂度

```Java
public class FlowContextBuilder {
```

```Plain Text
            │

                └─ ... (直到没有下游节点 → 返回 null → 递归终止)
```
